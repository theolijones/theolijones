Admin Guide — Onboarding a New Creator

Getting a new talent installed on Bet Tips and set up with templates

Onboarding is two separate jobs: getting the app onto their iPhone (Part A) and giving them an account + templates (Part B). The app isn't on the App Store yet, so installs go through EAS ad-hoc distribution — which means each new device is registered once, then you rebuild.

At a glance
  1. Register the creator's iPhone (eas device:create) — they open a link on their phone
  2. Rebuild the app so their device is included (eas build --profile preview)
  3. Send them the install link from the build page
  4. Issue a signup token in the admin app and send it to them
  5. After they sign up, upload their metadata template JSON(s) in the admin app
Part A — Get the app onto their iPhone
1

Register their device

In Terminal, from the mobile project:

cd ~/betting-tips-video-app/bet-tips/mobile eas device:create
  • Choose “Website” when asked for the registration method.
  • It prints a URL + QR code. Send the URL to the creator; they open it on their iPhone and install the profile it offers.
  • Run eas device:list to confirm the device appears. You can register several people before rebuilding.
2

Rebuild so their device is included

Ad-hoc builds embed the allowed-device list, so a device registered after a build isn't covered until you rebuild:

eas build -p ios --profile preview

EAS regenerates the provisioning profile with all registered devices (accept the Apple prompt if it appears). Takes ~5 minutes.

3

Send them the app

  • Open the finished build on expo.dev → Projects → bet-tips → Builds.
  • Share that build page link. The creator opens it on their iPhone and taps Install — installs over the air, no cable.
TestFlight isn't available yet. Apple now requires an Xcode 26 build, which the current Expo SDK 51 can't compile. Until an SDK upgrade, use this ad-hoc flow (cap: 100 devices/year, one rebuild per new device).
Part B — Give them an account & templates
4

Issue a signup token

Open the admin app (run npm run dev in bet-tips/admin, then visit the local URL it prints, e.g. http://localhost:5174).

  • Go to Signup Tokens → optionally pick the creator's talent (sets initials for content-type fields) → Issue token.
  • Send the generated token to the creator. It's single-use.
5

They sign up

The creator opens Bet Tips and signs up with their Sportsbet username + the token. Their account now exists on the backend.

6

Upload their metadata templates

  • Admin app → Users → find the creator → Manage templates.
  • Add template → upload a metadata JSON file → give it a clear name (e.g. “AFL Best Bet”) → repeat for each template → Save.
Each template is a fixed, complete metadata JSON. In the app the creator only enters the Bet ID, which is written into the FeedTipId field before the metadata is uploaded with their video. The row flags whether a FeedTipId field is present in your file.
That's it — the creator can now record, pick a template, enter a Bet ID, and submit. Pair this with the creator-facing “Getting Started” guide when you send their links and token.
